# DEC-030: MaiRecipe を「レシピと献立」から「食事まわり全部」へ広げる（作った・食べた・ふりかえり）

- Status: Accepted
- Date: 2026-10-27
- 決めた人: Eiichi
- 関連: DEC-010（取り込み → 改良 → 献立 → 買い物）/ DEC-012（AI は押した時だけ）/ DEC-013（版とメモ）/ DEC-028・029（AI 献立・AI レシピ）/ 図：MaiRecipe 食事の輪（Claude のアーティファクト）

## 背景
計画する → 買う → 作る までは一通りそろったが、作ったあとが何もつながっていない。
料理モードを最後まで進めても記録が残らず、使った食材は冷蔵庫に残ったまま。「最近作った」は献立に入れたかどうかでしか分からない。
食べたものの記録がたまれば、「今週は魚が少なめ」のようなふりかえりと、それを次の献立に戻すことができる。将来のレシピ SNS でも「作った記録」が投稿の元になる。

## 決定
1. MaiRecipe の範囲を「食事まわり全部」にする：計画する → 買う → 作る → 食べる → ふりかえる → また計画する、の輪
2. **共有（グループ）と個人の線引き**
   - 共有：レシピ・版・メモ、冷蔵庫、献立、買い物リスト、**作った記録**（どのレシピのどの版を・何人分・誰が作った・写真）
   - 個人（本人だけに見える）：**食べた記録**（いつ・何を・何人前）、評価、目標カロリー、体重
   - 「作った！」が共有と個人のつなぎ目。押したときにメンバーの顔チップで「誰が食べた？」を選ぶ。既定は全員が1人前
3. **作った記録**：料理モードの最後とレシピの画面から。版に紐づける。写真は任意。使った食材を冷蔵庫から消す候補を出し、チェックしたものだけ消す
4. **評価**：「また作る・ふつう・いまいち」の3段階を、作った記録ごと・人ごとに持つ。レシピの一覧では、レシピごとにまとめた値（作った回数・最後に作った日・また作るの回数・最新の評価）で絞れる。既定は自分の評価
5. **食べた記録**：作った！から1タップ（材料と人数から計算、AI なし）／外食・買ったものは写真（AI が料理を当てて概算、押した時だけ）か文字／記録しない、も選べる。一緒に食べたときは「相手も同じ」を1タップ
6. **ふりかえり**：直近7日を転がして計算する（記録が入るたびに更新。週のまとめは同じ計算の見せ方）。
   まずは食品のグループ（主食・肉魚卵豆・野菜・きのこ海藻・乳・果物）でのバランスと作った回数・外食の回数。カロリー・塩分（食品成分表）はそのあと。
   足りないものは「今日のおすすめ」と AI 献立の希望に反映する。言い方は「傾向」にとどめ、「不足です」「◯kcal 減らしましょう」とは言わない
7. 作る順：作った！ → 自分のレシピの1人前の計算 → 食べた記録 → 直近7日のふりかえりとおすすめへの反映 → 目標・体重

## 検討した別案と、選ばなかった理由
- 食べた記録も共有にする → 毎回一緒に食べるわけではなく、体重や目標は見られたくないことがある。最初から個人に分けないと後で直しにくい
- 1週間を暦でくくって月曜に集計 → 「次の食事はこうしたら」に効かない。転がす7日なら同じ計算で週のまとめも出せる
- 評価をレシピに1つだけ持つ → 2人で割れることがある。人ごとに持ち、一覧は自分の評価で絞る
- 写真から全部読む（カロリーも AI）→ 自分のレシピは材料と人数から計算できるので、AI は外食だけ。無料枠を節約でき、数字も安定する

## 影響
- データに「個人のもの」が増える。`forGroup` に加えて、本人だけに絞る口（セッションの userId）を data 層に足す。グループをまたいだ漏れのテストに「本人以外に見えない」を加える
- 冷蔵庫と「今日のおすすめ」が実際とずれにくくなる
- SNS（#27）では「作った記録」を公開にすると投稿になる。食べた記録・カロリー・体重は公開しない
- AI の無料枠は、外食の写真と「ひとこと」だけに使う
