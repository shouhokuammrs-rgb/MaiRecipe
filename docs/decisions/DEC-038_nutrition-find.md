# DEC-038: 栄養の目安は成分表から計算する。「栄養で探す」は AI なし

- Status: Accepted
- Date: 2026-11-25
- 決めた人: Eiichi（「鉄分が足りていない、ビタミンが足りていない、と思ったときに、今あるレシピからおすすめしてほしい」。方針に OK）
- 関連: DEC-012（AI は押した時だけ・出典を分ける）/ DEC-032（食材の名寄せ）

## 決定
- 栄養の数字は AI に作らせない。「日本食品標準成分表（八訂）増補2023年」の値に、材料名と分量を当てはめて計算する
- 3 回に分けて出す：①成分表の土台と「栄養で探す」（これ）②「このレシピに足すなら」③ AI への相談と新しいレシピ案
- 対象は 8 つ：鉄・カルシウム・たんぱく質・食物繊維・ビタミン A・B1・C・D
- レシピの一覧に「栄養で探す」。栄養を 1 つ選ぶと、自分のレシピ（最新版）を多い順に並べる。「少なめ」のレシピは出さない
- レシピの画面に「1人前に多く含まれる栄養（目安）」。多い栄養が無い・目安を出せないレシピには何も出さない
- **細かい数字（mg）は画面に出さない**。「多い／ふつう／少なめ」の 3 段階。多い ＝ 1人前で 1日の目安の 4分の1 以上、ふつう ＝ 10分の1 以上
- 1日の目安は「栄養素等表示基準値（2025）」（18歳以上。食品表示基準 別表第10）。性別・年齢で分けない 1 つの物差しにする
- **当て推量をしない**：成分表に当てはまらない食材・グラムに直せない分量は「分からない材料」とし、分からない材料の方が多いレシピには目安を出さない。調味料・水は、分からなくても数えない
- 人数が書かれていないレシピは 2人分として計算し、そう書く
- 画面に「目安です」「加熱での増減は入れていません」「体の不調があるときは医師や管理栄養士に」と出典を書く。サプリは勧めない

## 作り
- 食材の対応表は `scripts/nutrition/foods.tsv`（材料名に当てる正規表現 → 成分表の食品番号 → 1個・1本などの目安の重さ）。`scripts/nutrition/build.py` が成分表の Excel から `src/shared/nutrition-data.ts` を作る。**数字を手で書かない**。食材を足すときは tsv に行を足して流し直す
- 計算は `src/shared/nutrition.ts` の 1 か所（`recipeNutrition`・`rankByNutrient`・`highNutrients`）
- API は `GET /api/recipes/nutrition`（最新版の材料と人数を返すだけ）。計算は画面で行う（成分表に当てはめる処理を Worker の CPU 10ms に載せない）。テーブルは足していない
- 1個・1本の重さは成分表の値ではなく、台所での一般的な目安
- 殻つきの貝（あさり・しじみ）・骨つきの手羽は、成分表の廃棄率を引いて食べられる分だけ数える
- 乾物と生（わかめ・ひじき）は別の行にする。必ず加熱して食べるじゃがいもは「水煮」の値を使う。レモンは果汁の値（1個 ＝ 果汁 30g）
- 食材の名前を含むだけの物（だし・ジャム・ジュース・粉・料理名）は当てない（`NOT_THE_FOOD`）
- 単位の無い数字は 10 までを個数とみなす（「豚肉 200」を 200 パックと読まない）。厚さの分からない肉の「枚」は数えない
- 肉・魚が「適量」のときは「分からない材料」に数える
- 成分表の備考に「ビタミンC：酸化防止用として添加された食品を含む」とある加工品（ハム・ベーコンなど）は、ビタミン C を数えない

## 選ばなかった案
- 全部 AI に聞く → もっともらしい数字を作ることがあり、聞くたびに変わる。体のことなので使わない
- 外部の栄養計算サービス → 多くが有料か、日本の食材に弱い
- mg まで出す → 分量をグラムに直す時点で誤差があるのに、正確そうに見える
- 計算結果を DB に持つ → 対応表を直すたびに作り直しが要る。レシピの数なら画面で計算して足りる

## 影響
- 対応表に無い食材が多いレシピは並ばない（画面に件数を出す）。足りない食材は tsv に足していく
- 生の値で計算するので、ゆでる・炒めるで減るビタミン C などは多めに出る
