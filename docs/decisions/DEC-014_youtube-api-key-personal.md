# DEC-014: YouTube の概要欄は Eiichi 個人の API キーで読む（2人で使う間だけ）

- Status: Accepted
- Date: 2026-09-28
- 決めた人: Eiichi
- 関連: docs/spec.md §3（#7・#13）/ DEC-011 / DEC-012

## 背景
YouTube の料理動画を取り込むと、題名しか入らず、材料と作り方を毎回手で入れていた。
材料と作り方は動画の概要欄に書いてあるか、概要欄にレシピサイトの URL が貼ってあることが多い。
概要欄を読むには YouTube Data API v3 のキーが必要（題名だけなら鍵の要らない oEmbed で取れる）。

## 決定
- 概要欄は YouTube Data API v3（videos.list?part=snippet）で読む。キーは **Eiichi 個人のキー**を
  `wrangler secret put YOUTUBE_API_KEY` で入れ、Eiichi とパートナーの2人で使う間だけ使う
- キーを使うのは `src/api/platform/` の中だけ。画面や返事にキーを出さない。キーが無いときは今まで通り題名だけ
- 概要欄に【材料】【作り方】の区切りがあればそこから、無ければ概要欄に貼られた URL を上から最大3件読んで、
  取れたページを出典にする（動画は動画として残す）。どちらも AI は使わない（DEC-012）。取り出すのは材料と手順だけ（DEC-011）
- **一般公開するときは別の方式に切り替える。どの方式にするかは未決**

## 検討した別案と、選ばなかった理由
- 動画ページの HTML を直接読む → YouTube の利用規約に触れるおそれがあり、ページの形が変わると壊れる
- 使う人がそれぞれ自分のキーを入れる → 2人で使う今は手間が増えるだけ。一般公開時の候補として残す
- AI で動画の内容から材料を起こす → AI は押した時だけ・既定オフ（DEC-012）。M4 で検討

## 影響
- ユーザーには：YouTube の URL を貼ると、概要欄かリンク先のレシピから材料と作り方が入る。出典にはレシピのページ、動画は動画として並んで見える
- 運用：API の無料枠（1日 10,000 ユニット、videos.list は1回 1 ユニット）の範囲で使う。キーは Eiichi の Google Cloud プロジェクトに紐づく
- 見直すとき：一般公開する前。利用者ごとのキー・サーバー側の割り当て管理・別の取得方法のどれにするかを決めて、新しい ADR を書く
