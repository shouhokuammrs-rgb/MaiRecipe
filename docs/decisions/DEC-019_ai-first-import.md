# DEC-019: 取り込みは「正確さ優先・一発で」。構造化データが無ければ最初から AI で読む

- Status: Accepted
- Date: 2026-10-19
- 決めた人: Eiichi
- 関連: DEC-016 / DEC-017（置き換え）/ DEC-018 / Issue #36

## 背景
DEC-017 では、まず規則（見出し・概要欄の形）で読み、材料か手順が 0 のときだけ AI に回していた。
規則は「1つでも取れたら読めた」と判断するので、次のような崩れが起きた。
- 2品ある動画で材料が混ざる（「塩（塩焼き）」のような名前になる）
- 他の人のコメントから分量を拾ってしまう
- 概要欄の材料と AI の手順を後からつなぎ合わせるので、噛み合わない
Eiichi の判断：待ち時間があっても、一発で正確なレシピが作れるほうが使いやすい。

## 決定
URL の取り込みは次の順にする。
1. **作者が機械向けに書いたレシピ（JSON-LD の構造化データ）**があればそれを使う。ページそのもの、または動画の投稿者が概要欄・自分のコメントに貼ったページ。速くて（0.5 秒）正確なので AI は使わない
2. 無ければ **AI**
   - 動画：Gemini に動画を見せる（DEC-018）。概要欄と投稿者のコメントを手がかりとして渡し、材料名と分量は概要欄を優先させる。だめなら文章を読む AI（Workers AI）
   - ページ：本文を Workers AI に読ませる
3. **AI が使えないとき（無料枠切れ・不通・鍵なし）だけ**、規則で読む。上限・不通のときは理由を添える

## 影響
- 構造化データの無いページ・動画の取り込みは 10 秒〜1 分かかる（画面に目安を出す）
- 無料枠の使う量が増える。ふたりで使う分には足りる。一般公開のときは見直す（DEC-017 と同じ）
- 規則での読み方は、AI が使えないときの予備として残す（テストもそのまま）
- 本文を集めるときに JSON-LD を読めなくなる不具合（同じ script 要素に終わりの handler を2つ付けていた）を直した
