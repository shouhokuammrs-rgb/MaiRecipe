# DEC-039: 人数は元のレシピの数を使う。分からないときだけ人が入れる

- Status: Accepted
- Date: 2026-11-26
- 決めた人: Eiichi（「元々のレシピが何人分かで識別するべきでは？」）
- 関連: DEC-038（栄養の目安。1人前で出すので、人数がずれると倍に出る）

## 背景
「栄養で探す」で、29 件中 13 件が「2人分として計算」になっていた。人数が無いレシピを 2人分で割ると、3〜4人分のレシピが上位に並ぶ。
元のレシピから人数を読む仕組みはすでにあった（取り込みのとき／人数を読む前に保存したレシピは、開いたときに 1 回）。抜けていたのは次の 3 つ。
- 読める書き方が「2人分」「2人前」だけで、「材料（2人）」「3名分」「二人分」「4 servings」を読めなかった
- 開いたことのないレシピは、探してもいなかった
- 一度探して無かった（0）レシピは、二度と探さなかった

## 決定
順番は 3 段。上から順に試し、当て推量はしない。
1. **元のレシピから読む**。読める書き方を広げる（`src/shared/servings.ts`）：材料の見出しのそばの「2人」「3名」、どこにあっても「名分」「人用」「二人分（漢数字）」「4 servings / serves 4」
2. **人数の無いレシピは、元のレシピをもう一度読んで人数だけ埋める**。「栄養で探す」を開いたときに、人数の無いレシピを 1 つずつ順に探す（1 回 40 件まで）。前に探して無かった（0）レシピも、1 つの端末につき 1 回だけ探し直す（`POST /api/recipes/:id/servings?again=1`）。材料・手順は変えない
3. **それでも分からないレシピだけ、その場のボタンで人が入れる**（1〜6人分。`PUT /api/recipes/:id/servings`）。「栄養で探す」の行と、レシピの画面の材料の上に出す

- 人数を入れても新しい版は作らない（材料も手順も変わらず、分からなかった人数が分かっただけ）。人数の無い版（null・0）にだけ書く
- 1 以上の人数が入っている版（元から読めた・人が決めた）は、探し直しでも手入力でも上書きしない
- 米の量や材料の重さから人数を推定することはしない（外れたときに気づけない）

## 選ばなかった案
- 人が入れるボタンを主役にする → 元のレシピに書いてある数が正しい。人に聞くのは最後
- 探し直しを AI（動画を見る）で行う → 回数の上限を使う。人数だけのために使わない。動画は概要欄から読み、無ければ人が入れる
- 探し直した印をサーバーに持つ → テーブルの列が増える。端末で覚えれば足り、覚えられなくても害は無い（もう一度探すだけ）

## 影響
- 「2〜3人分」は少ない方（2）で読む（前からの決まり）。1人前は多めに出る
- 動画で、概要欄に人数が無いレシピは 3 に進む
