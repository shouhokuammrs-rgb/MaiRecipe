# DEC-003: 認証はメール + パスワードのみにする

- Status: Accepted
- Date: 2026-09-02
- 決めた人: Eiichi
- 関連: docs/spec.md §3 / docs/spec.md §4

## 背景

ログイン方法を増やすほど、外部サービスの登録・リダイレクト設定・アカウント紐付けの実装と検証が増える。
このアプリは1人または家族単位で使うもので、ソーシャルログインで得られる登録率の向上は目的ではない。

## 決定

メールアドレスとパスワードによる登録・ログイン・パスワード再設定のみを提供する。
Google 等の OAuth ログインは実装しない。

## 検討した別案と、選ばなかった理由

- 案B: Google ログインを追加 → 外部設定と検証の手間が増える。登録率は目的ではない
- 案C: マジックリンクのみ → メールが届かないときの回復手段が乏しく、パスワード方式より運用が難しい

## 影響

- ユーザーはメールアドレスとパスワードで登録し、確認メールのリンクを踏む
- パスワードは8文字以上をアプリ側で要求する
- 後から OAuth を足す場合、既存アカウントとの紐付け方を改めて決める必要がある
