# DEC-006: 課金は Stripe で行い、MVP では課金せず機能フラグで後付けする

- Status: Accepted
- Date: 2026-09-02
- 決めた人: PM（Eiichi 承認済み）
- 関連: docs/spec.md §3 / DEC-001

## 背景

無料・プレミアム・Pro の3段階のプラン構成を踏襲する予定だが、
作りきる前に課金を入れると、動くものを触れるまでが遠くなる。
Web アプリなのでアプリストアの課金を通す必要はない。

## 決定

決済は Stripe を使う。ただし MVP の段階では課金を実装せず、全機能を使える状態にする。
プランによる制限は機能フラグで後から入れる。実装は M5。

## 検討した別案と、選ばなかった理由

- 案B: RevenueCat → アプリストア課金の抽象化が主目的で、Web のみの構成では利点がない
- 案C: 最初から課金を実装 → 動くものが遠のく。学習目的に対して優先度が低い

## 影響

- 当面ユーザーはすべての機能を使える
- プラン判定を後から差し込めるよう、機能の呼び出し口を1か所にまとめておく
- 課金を入れる時点で、既存ユーザーの扱い（移行措置）を改めて決める必要がある
