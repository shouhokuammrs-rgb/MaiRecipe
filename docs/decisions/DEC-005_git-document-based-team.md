# DEC-005: チーム運用を Git ドキュメントベースにし、PM が担当者間を仲介する

- Status: Superseded by DEC-007
- Date: 2026-09-02
- 決めた人: PM（Eiichi 承認済み）
- 関連: DEC-007

## 背景

PM・Engineer・Designer がそれぞれ別のセッションで動くため、状態の共有手段が要る。
チャットで口頭伝達すると Eiichi が伝書鳩になり、記録も残らない。

## 決定

状態はすべて Git 上のドキュメントに置く。PM が唯一の真実となる進行表を持ち、
Engineer への指示書と完了報告、Designer への仕様書をファイルでやり取りする。
担当者間の伝達は PM が行い、Eiichi には判断だけを求める。

## 検討した別案と、選ばなかった理由

- 案B: Notion 等の外部ツール → Git とコピーが二重管理になり、どちらが正か分からなくなる
- 案C: チャットで都度共有 → 記録が残らず、Eiichi が伝書鳩になる

## 影響

- Eiichi は判断だけすればよく、担当者間の伝達をしなくてよい
- ドキュメントの更新漏れがそのまま情報の欠落になる
- 進行表が肥大化し、GitHub 上の課題管理と二重になる問題が後に判明した → DEC-007
