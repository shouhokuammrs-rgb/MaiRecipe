# 献立：1食に複数の品（#37）設計

- 日付: 2026-09-29
- Issue: #37（M3 献立と買い物の続き）
- 前提: #14（パートナーの招待）の上に積む。#14 の「献立がぶつかったら招待した側を残す」をここで「両方残す」に変える
- 進め方（Eiichi, 2026-09-29）: 仕様と計画は確認を待たずに実装まで進める。**本番 D1 への移行の前だけ止めて聞く**

## 1. 目的と完了条件

朝・昼・晩の1つの枠に、主菜・副菜・汁物のように複数のレシピを入れられるようにする。

完了条件
- 1つの枠に何品でも足せる（同じレシピは1つの枠に1回まで）。品ごとに消せる。上下に並べ替えられる
- 買い物リストは、枠の中の全品の材料を合算する
- #14 の参加で献立の枠がぶつかったら、両方残す（招待した側の品が先、参加した人の品が後ろ）。完了画面の「もとの献立を残しました」は出なくなる
- 既存の献立（1枠1品）は、移行後もそのまま1品として残る。移行の前後で本番の献立の件数が変わらない
- `npm run lint && npm run typecheck && npm run test` と E2E が通る

作らないもの: 品の種類（主菜・副菜）の入力欄、枠ごとの人数、品の上限（UI で困ったら後で決める）

## 2. データ

`meal_plans` を「日付 × 朝昼晩 × 並び順つきの複数レシピ」にする。

| 変更 | 内容 |
|---|---|
| 列を足す | `position integer not null default 0`（枠の中の並び順。小さいほど上） |
| 索引を消す | `meal_plans_slot_uq`（group_id, date, meal）の unique |
| 索引を足す | unique `meal_plans_item_uq`（group_id, date, meal, recipe_id）＝同じ枠に同じレシピは1回まで |
| 索引を足す | `meal_plans_slot_idx`（group_id, date, meal）＝枠の読み書き用（unique ではない） |

- 既存の行は `position = 0` のまま。1枠1行なので、そのまま「1品だけの枠」になる。行を消したり作り直したりしない
- マイグレーションは ALTER TABLE ADD COLUMN と索引の作り直しだけ。テーブルの作り直し（コピー）が生成されたら、手で ADD COLUMN の形に直す
- 移行の手順（本番）: ①件数を数える ②バックアップ（`wrangler d1 export --remote`、または D1 の Time Travel の時刻を控える）③マイグレーション ④件数が同じことを確かめる ⑤デプロイ。①〜④の間は古いコードが「枠を上書き」しようとして失敗するので、③と⑤の間を空けない

## 3. API

グループの判定はこれまで通りセッションからだけ。行の id を受け取る操作は、必ず自分のグループの行か確かめる（他グループの id は 404）。

| メソッド | パス | 内容 |
|---|---|---|
| GET | /api/plans?from&to | 返り値の各行に `id` と `position` を足す。並びは date → 朝昼晩 → position |
| PUT | /api/plans | { date, meal, recipeId } を枠の**最後に足す**。すでに同じレシピがあれば何もしない（204）。過ぎた日は 400 |
| DELETE | /api/plans/items/:id | その1品を消す。過ぎた日は 400、他グループ・無い id は 404 |
| POST | /api/plans/items/:id/move | { direction: "up" \| "down" } で1つ上・下の品と入れ替える。端なら何もしない。過ぎた日は 400 |
| DELETE | /api/plans/:date/:meal | 残す（枠を丸ごと空にする）。画面からは使わなくなるが、古い画面が残っていても壊れないため |

- PUT の意味が「上書き」から「追加」に変わる。古い画面（PWA のキャッシュ）から呼ばれても、品が増えるだけで壊れない
- 足すときの position は「その枠の最大 + 1」を INSERT の中のサブクエリで決める（Worker で数えてから入れない）
- 並べ替えは、2行の position を入れ替える UPDATE を batch で流す

## 4. 買い物リスト

`shoppingSources` は献立の行ごとにレシピの材料を返しているので、1枠に複数行あれば自然に合算される。コードの変更は無く、テストで「1枠2品の材料が両方入る」ことを確かめる。

## 5. 参加（#14）の変更

- 「ぶつかる献立を消す」文をやめる
- 献立の付け替えで、参加した人の行の position に「招待した側の同じ枠の最大 position + 1」を足す（`coalesce((select max(h.position) + 1 …), 0)` を UPDATE の中で）。同じ枠に同じレシピが入ることは無い（レシピはグループごとに別の id）
- 返り値の `keptPlans` を無くし、完了画面の「もとの献立を残しました」の行も消す。説明文の「同じ日・同じ食事の献立がすでにあるときは、◯◯さんの献立を残します。」は「同じ日・同じ食事の献立は、両方並べて残します。」に変える
- `planSlotLabel` は使われなくなるので消す

## 6. 画面（献立）

- 枠の中に品を縦に並べる。各品：題名（押すとレシピへ）、上へ・下へ（端では出さない）、消す（×）。タップ 44px 以上
- 枠の最後に「＋品を追加」。押すと今のレシピ選びを開き、選ぶと最後に足す
- レシピ詳細からの「献立に入れる」（?add=）は、選んだ枠の最後に足す（上書きしない）
- 過ぎた日は今まで通り操作できない
- ローディング／エラー／空状態は今のまま

## 7. テスト

API（`test/api/plans.test.ts` など）
- 1つの枠に2品足すと、GET で position 順に2品返る。同じレシピは2回足しても1品のまま
- 品を1つ消すと、もう1品は残る
- 並べ替えで順番が入れ替わる。端での move は何もしない
- 他グループの品の id で消す・並べ替えると 404（「グループをまたいだ漏れがないこと」にも追加）
- 過ぎた日の品は消せない・並べ替えられない（400）
- 買い物リストに、1枠2品の材料が両方入る
- 参加（group.test.ts）: ぶつかった枠は両方残り、招待した側の品が先。`keptPlans` は返らない

マイグレーション
- 移行前の形（1枠1行）のデータを入れた状態からマイグレーションを当てても、行が消えず position = 0 になる（ローカル D1 で確かめ、結果を PR に書く）

E2E
- 献立の1つの枠に2品足し、1品消し、買い物リストに残った品の材料が出る
