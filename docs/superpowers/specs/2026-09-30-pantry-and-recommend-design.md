## 2. データ（PR1）

新しい表 `pantry_items`（冷蔵庫の中身。グループごと）

| 列 | 型 | 内容 |
|---|---|---|
| id | text PK | |
| group_id | text not null → groups（cascade） | |
| name | text not null | 名寄せ後の名前（`canonicalName`） |
| amount | text null | 量（任意、自由記述） |
| expires_on | text null | 期限 `YYYY-MM-DD`（任意） |
| added_on | text not null | 入れた日 `YYYY-MM-DD`（JST。「◯日前」の計算用） |
| created_at / updated_at | timestamp | |

- unique (group_id, name)。同じ名前をもう一度入れても2行にならない（入れた日は変えない）
- `shopping_marks` は残すが、使うのは **調味料の「家にない」印（kind=home, value=false）だけ**になる。kind=bought は使わなくなる

### 移行（1本の SQL マイグレーション。表を足して、印を移す）

1. `pantry_items` を作る
2. `shopping_marks` で value=1 の行（home でも bought でも）から、キーの「|」より前を名前として `pantry_items` に入れる（グループ×名前で重複はまとめる。`added_on` は移行した日）。キーの名前は買い物リストを作るときにすでに名寄せ済み
3. 「家にない」（home=0）印のうち、同じキーに「買った」（bought=1）があるものは消す（買ったので、今は家にある）
4. value=1 の印と、kind=bought の印をすべて消す。残るのは home=0 だけ

- 調味料の印も 2. で冷蔵庫に入ることがある（SQL では調味料かどうか判定できない）。冷蔵庫の一覧と点数では調味料を読み飛ばすので、見えないし害もない
- id は SQL で作る（`lower(hex(randomblob(16)))`）。移行だけで使う SQLite の関数で、検索や集計には使わない
- 本番の件数確認: 移行前に `shopping_marks` を kind・value ごとに数え、移行後に `pantry_items` の件数（＝value=1 の名前の種類数）と、残った `shopping_marks`（home=0 のみ）を数える

### グループへの参加（`membership.ts`）

参加する人の冷蔵庫は招待した側へ移す。**同じ名前がぶつかったら招待した側を残す**（買い物の印と同じ扱い）。参加の1つのトランザクションに「ぶつかる行を消す」「残りを付け替える」を足す。

## 3. API

グループの判定はセッションからだけ。DB は `forGroup` 経由だけ。id を受け取る操作は自分のグループの行か確かめる（他グループの id は 404）。

### PR1

| メソッド | パス | 内容 |
|---|---|---|
| GET | /api/pantry | 冷蔵庫の一覧 `{ items: [{ id, name, amount, expiresOn, addedOn }] }`。調味料は除く。並びは 期限が近い順（期限なしは後ろ）→ 入れた日が新しい順 → 名前 |
| POST | /api/pantry | `{ names: string[] }`（1〜30個、各1〜40字）。名寄せして入れる。空・調味料・すでにあるものは飛ばす。`{ added: string[], skipped: string[] }` |
| PATCH | /api/pantry/:id | `{ amount?: string|null, expiresOn?: "YYYY-MM-DD"|null }` |
| DELETE | /api/pantry/:id | 使い切った |
| GET | /api/shopping?days=N | 各品の `home` と `bought` を **`have: boolean`** 1つに替える。調味料以外は「冷蔵庫に同じ名前があるか」。調味料は「家にない」印が無ければ true |
| PUT | /api/shopping/have | `{ name, value }`。調味料以外: true＝冷蔵庫に入れる／false＝冷蔵庫から消す。調味料: true＝「家にない」印を消す／false＝「家にない」印を付ける |

- 無くすもの: `PUT /api/shopping/marks`、`DELETE /api/shopping/bought`
- 名前の判定は `shopSection(name) === "調味料"` と `canonicalName` を使う（買い物リストと同じ）
- 冷蔵庫と買い物の名前の照合は **名寄せ後の完全一致**（「鶏肉」が冷蔵庫にあっても「鶏もも肉」は隠さない）

### PR2

| メソッド | パス | 内容 |
|---|---|---|
| GET | /api/recommend | `{ main: Reco[], side: Reco[], soup: Reco[] }`。各10件まで、点数順。`Reco = { id, title, category, have: string[], soon: string[] }` |

- 「これを使いたい」は新しい API を作らず、今ある「材料から探す」（`POST /api/recipes/find`）に選んだ食材の名前を渡す。並びも同じ（使う数が多い順）
- 点数の計算は Worker で行うが、レシピ数が数百でも数ミリ秒以内（名前の比較だけ）

## 4. 点数（`src/shared/recommend.ts`、純粋関数・テスト必須）

入力: レシピ（id・名前・カテゴリ・最新版の材料・更新日時）、冷蔵庫（名前・期限）、献立（今日の7日前〜6日後の recipeId と日付）、今日。

1. 材料のうち調味料を除き、名寄せして重複を消したものを「主な材料」とする。主な材料が0なら 使用率は0
2. 使用率 = 冷蔵庫にある主な材料の数 ÷ 主な材料の数 × 100。照合は「材料から探す」と同じ `matchesIngredient`（冷蔵庫の「豚肉」は材料の「豚こま肉」に当たる）
3. 期限が近い: 当たった冷蔵庫の食材のうち、期限が今日から3日以内（過ぎたものも含む）1つにつき +15
4. 過去7日（今日の7日前〜昨日）の献立に入っていたら −25
5. 今日〜6日後の献立に入っていたら −60（4. と重なれば両方引く）
6. 並び: 点数が高い順 → 更新日時が新しい順 → 名前
- 返す `have` は当たった主な材料の名前（レシピ側の表記）、`soon` はそのうち期限が近いもの
- 分類: main＝主菜・丼、side＝副菜、soup＝汁物。デザート・その他は出さない

## 5. 画面

### 冷蔵庫（新しいタブ `/fridge`。PR1 で一覧・追加・編集・使い切った、PR2 でおすすめ・これを使いたい）

- 見出し「冷蔵庫」と右上に「＋ 食材」。押すと下から入力シート：名前の入力欄＋マイク（今の MicButton）。「玉ねぎ にんじん 豚こま」のようにスペースや読点で区切るとまとめて入る。Enter か「入れる」で追加。入れた数をトーストで出す。飛ばしたもの（調味料・すでにある）があれば一言添える
- 一覧（期限が近い順）：各行に 選ぶチェック（PR2）・名前・「今日 / ◯日前に入れた」・期限（3日以内は赤字）・量・「使い切った」。「使い切った」は1回目で「本当に消す？」に変わり、2回目で消える
- 行の名前を押すと、量と期限を直すシート（期限は日付入力。「期限なし」に戻せる）
- 空: 「冷蔵庫は空です。右上の「＋ 食材」か、買い物リストのチェックで入ります。」
- 下に一言：「調味料（醤油・味噌など）は冷蔵庫に出さず、いつも家にある扱いです。」
- **今日のおすすめ（PR2、デモのとおり）**：カード1枚。見出し「今日のおすすめ」と右に「⇄ ほかの組み合わせ」。1品1行（選択の四角・分類・レシピ名・使う冷蔵庫の食材。期限が近い食材は赤字）。行を押すと入れる／外す。右の ⇄ でその分類だけ次の候補へ。ボタン「◯/◯の夜に ◯品入れる」（0品なら無効で「入れる品を選んでください」）。その下に「‹ 前の日」「次の日 ›」（今日より前には戻らない）。入れる先の初期値は今日から14日以内で最初に空いている夜（無ければ今日）。入れたらトースト「◯/◯（◯）の夜に◯品入れました。献立タブで見られます」
  - 候補のめくり方: 組み合わせ番号 i と分類ごとの ⇄ 回数 k で、各分類の候補を `(i + k) % 件数` 番目にする（`src/shared/recommend.ts` の純粋関数）
  - どの分類にもレシピが無いときはカードを出さない。冷蔵庫が空でもカードは出す（点数は献立の重なりだけで決まる）
- **これを使いたい（PR2）**：一覧のチェックで食材を選ぶと「◯個を使いたい → レシピを探す」ボタン。押すと下に「「玉ねぎ・にんじん」を使うレシピ」の一覧（使う数と名前、分類）。各行に「献立へ」（最初に空いている夜に入れる）。0件なら「保存したレシピには、この食材を使うものがありません。」

### 買い物（PR1）

- 各行の左に チェック1つ（44px 以上）。押すと冷蔵庫に入って（調味料は「家にある」に戻って）リストから消える。トースト「「玉ねぎ」を冷蔵庫に入れました」
- 「家にあるものを隠す」のスイッチは「冷蔵庫にあるものも表示（◯件）」に変える（既定はオフ＝隠す）。表示中はチェック済みの行を薄く・取り消し線で出し、チェックを外すと冷蔵庫から戻る
- 見出し右の「残り ◯ / ◯」は「残り ◯品」（まだチェックしていない品の数）に
- 全部チェックしたら「全部そろっています。冷蔵庫に入っています。」

## 6. テスト

- `test/shared`: 点数（使用率・調味料除外・期限の加点・過去／今週の減点・同点の並び・主な材料0）、候補のめくり方、最初に空いている夜、冷蔵庫に入れる名前の分割と名寄せ
- `test/api`:
  - 冷蔵庫の 追加（まとめて・名寄せ・調味料は飛ばす・重複は飛ばす）・一覧の並び・直す・消す
  - 買い物の `have`：冷蔵庫にあれば true／調味料は既定 true、「家にない」で false／`PUT /shopping/have` の往復
  - マイグレーション：印が冷蔵庫へ移り、残るのは home=0 だけ・買った調味料の「家にない」は消える
  - 参加：冷蔵庫が招待した側へ移り、ぶつかる名前は招待した側が残る
  - **グループをまたいだ漏れ**：他人の冷蔵庫が 見えない・直せない・消せない（404）・買い物の `have` に効かない・おすすめに他人のレシピが出ない
- E2E: 冷蔵庫に入れる → 買い物で隠れる → 使い切る。PR2 でおすすめを献立に入れる
